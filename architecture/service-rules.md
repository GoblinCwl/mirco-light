# 两个服务的规则

本文中的两个服务指 `quartz4`（Quartz 构建端）和 `quartz-server`（Go 业务后端），不表示部署中只有两个进程或容器。

## 1. Quartz：负责页面与构建

| 范围 | 规则 |
| --- | --- |
| 输入 | 文章文件、页面配置、模板、组件与浏览器资源 |
| 输出 | `public/current/` 静态产物，以及成功构建的私有内容/权限/构建状态快照 |
| 常驻原因 | 当前以 `build --watch` 运行，需要监听文章与源代码变化并热更新 |
| 浏览器逻辑 | 页面展示、播放器控制、星轨绘制、表单交互等前端代码仍在 Quartz 工程，构建后交给浏览器执行 |
| 业务边界 | 不启动访客统计或适配后台，不维护本站数据库，不保存管理员会话，不直接做平台定时同步 |
| 管理重载 | 只通过私有 Unix socket 接受受限的重载与发布规则请求，不提供任意命令执行 |

文件变化后由 Quartz 构建，成功时原子替换文章索引快照；Go 消费快照更新服务器索引、运行纪事和评论权限。构建失败不替换上一次成功的文章快照。生产构建启用 `QUARTZ_ATOMIC_PUBLISH=1`：产物先写入 `public/.releases/build-<id>/`，成功后通过原子替换 `public/current` 相对软链接发布；Nginx 与 Go 的静态读取都使用 `current`。完整构建从空版本开始，增量构建复制当前版本后再修改，失败时丢弃候选版本，继续服务旧站点。保留当前和上一个成功版本，发布后清理更早版本；不移动或清空作为容器挂载点的 `public/` 本身。页面发布后再写私有快照，两个目录之间不保证跨目录事务。

新构建实例在扫描、读取文章前建立文件监听。初次构建期间的文件变更先缓冲，内容缓存就绪后复用现有增量构建消费，避免修改落在监听空窗；不增加周期任务。“隐藏展示”仅影响公开入口，文章仍参与构建与监听。加密文章手动提交密码时按本次输入派生密钥，缓存密钥只用于无密码输入的自动解锁，避免修改密码后旧密钥覆盖新输入。

“只负责构建”约束的是服务器进程职责；Share、Repo、Video 等页面及其前端交互仍由此工程实现。

Quartz 容器内的主进程负责源码编译、源码监听、本地预览和重载 socket；一份受控构建子进程负责当前完整构建及后续文章热更新。源码或发布规则重载时，先关闭旧文章监听、等候已排队的写入和发布完成，再退出整个旧构建子进程，重新编译并启动下一份实例。主进程不再通过随机查询参数反复导入大型 ESM bundle；旧实例的模块、AST、插件缓存与原生内存随进程退出释放。只保留一份活动构建实例，不增加业务服务或容器。

构建锁由主进程持有，子进程通过私有 IPC 申请与释放，因此完整构建、文章增量发布及非原子模式下的本地预览读取仍按原规则串行。子进程异常退出会释放它持有的锁；完整构建失败时继续提供上一份已发布产物，源码修复或重新重载可再次启动构建。已就绪的子进程意外退出时，主进程按事件自动尝试恢复一次；若仍失败则等待源码修改或管理员重载，不设周期重启。旧进程退出设有有界等待，超时会结束该构建实例并报告失败。

监听器在注册底层监听之前跳过隐藏工具目录、明确排除的目录与被发布规则排除的文件。源码监听限定于 Quartz 源码、静态资源和根配置/依赖文件，跳过依赖目录、构建缓存、测试和文档；仅链接可见目录属于可发布文章，仍持续监听。文章变化只触发当前子进程的增量构建，不为每次保存重启完整构建。 2026-11-11 验证覆盖六轮实际站点完整重构、原生图像依赖退出、文章/标签索引增量发布、仅链接文章、管理重载及有界故障恢复；空闲工作集约 0.7–1.3 GiB，监听约 1080 个。该数值仅对应当时数据与依赖规模，构建峰值和空闲回收会浮动。


## 2. Go：负责运行时业务与统一持久化

| 范围 | 规则 |
| --- | --- |
| 请求 | 公开/管理员 API、访客统计、Share 路由校验、平台及媒体适配 |
| 后台任务 | 四源索引、视频和用户资料同步、运行纪事、Artalk 权限同步、活动聚合等 |
| 本站数据 | MySQL 管理配置、认证状态、索引与标签、友链、反馈、访问记录、平台缓存和运行纪事 |
| 私有文件 | 仅保留必要身份/加密密钥、部署密码及受控的外部镜像凭据投影 |
| 第三方数据 | 第三方自身仍是源数据的管理者；需要写入时使用相应 API，不写第三方挂载数据库或仓库 |
| 生命周期 | 持续运行；停止后静态页面仍可由 Nginx 提供，但动态能力不可用 |
| 故障处理 | 有有效缓存的模块保留缓存并报告错误；不能把上游失败解释为成功或空库，进而误删索引 |

Jellyfin 的播放协商、转封装、转码由 Jellyfin 提供，Fontinass 参与其现有字幕链路。Go 不编码视频，负责本站分享权限、凭据隔离、会话和受限资源代理；浏览器播放器与弹幕交互仍在 Quartz 前端。Bilibili 使用官方 iframe 播放，与 Jellyfin 播放链路不同。

## 3. 数据更新规则

| 数据 | 当前更新触发 |
| --- | --- |
| 文章索引 | Quartz 首次成功构建及后续热更新发布快照；Quartz 通过私有 Unix socket 通知 Go；Go 启动时补读快照，相同快照跳过 SQL，失败才延时重试 |
| 分享索引 | 本站分享操作后立即同步，后台默认每 1 分钟检查 OpenList 来源；只索引分享项目首页，子目录继承所属首页；不索引管理员空间 |
| 仓库索引 | 启动时及后台默认每 5 分钟检查 Gitea 当前仓库来源；GitHub 新代码事件触发镜像任务完成后立即刷新仓库索引 |
| 视频索引 | 启动读取已有快照；视频同步完成、详情刷新或数据管理修改后通知单一索引任务。通知合并，失败延迟重试；不再轮询未变化的视频库 |
| GitHub / Bilibili 用户与活动 | 后台默认每 30 分钟同步，使用服务器缓存和本站头像资源；GitHub 同轮检查公开代码事件，高水位变化才触发镜像同步 |
| 日历 | 读取限定日记标记；文件变化后等待约 60 秒安静期聚合 |
| ActivityWatch 汇总 | 后台默认每 10 分钟刷新 |
| Artalk 页面权限 | 文章成功快照导入后或相关配置变更时触发，成功项留检查点；失败才重试 |
| 运行纪事 | 内容纪事与索引在同一事务写入；构建及容器恢复沿用现有快照任务，按类型和展示内容去重、保留最新发生时间，并只保留最近 10 条；同一服务的 restart/recreate 视为相同的服务恢复记录 |
| GitHub Token 投递 | Go 启动、凭据保存或清空后触发；仅失败时重试，不再每分钟轮询 |
| 搜索 / 标签 / 星轨 / 流新 / RSS / 拾遗 | 复用服务器统一索引；读取时仍遵守公开范围和解密权限，不向浏览器下发未授权内容正文 |

四类来源统一按条目比较语义版本、路由、日期与扩展信息，只写入新增或变化条目，移除来源已删除的条目；不以语义摘要单独决定是否变化，避免遗漏视频播放数、封面、系列等扩展信息。未变化时不执行 content、content_sources、纪事或订阅元数据写入；仍会读取来源和索引元信息并取得同步锁。`content_sources.checked_at` 记录首次初始化或实际应用索引变化的时间，不表示每次轮询时间。Video 的事件触发机制与平台同步周期保持不变。

首页活动状态前端刷新间隔为 30 秒，页面隐藏时不请求；QQ 状态仍为 60 秒。视频管理面板仅在同步任务进行或等待结果时每 2.5 秒查询状态，完成后停止，不会因此重复触发平台同步。

GitHub 镜像链路：现有用户活动刷新对比本人仓库的创建/提交动态内容（包含每天的提交次数变化），同时读取 GitHub 公开事件（最近 100 条），处理本人仓库的 Push/Create/Delete/Public/Release；忽略议题、议题评论和其他账号仓库。`repo_snapshots` 的 `mirror-events:v1` 保存成功消费的最大事件 ID 与代码动态摘要；公开事件流延迟时仍可由新贡献动态触发，旧事件过期或议题挤出列表不会反复触发。新事件通过共享目录下 `sync.sock` 的私有 Unix HTTP `POST /sync` 通知独立 `gitea-github-sync`，不增加周期任务、不开放公网入口。事件源有 GitHub 自身延迟，仍保留现有每小时仓库发现和 Gitea 原生每小时镜像拉取兜底，不能承诺推送后实时更新。
GitHub 贡献统计可能遗漏作者邮箱未关联账号的提交。现有仓库索引任务从公开 Gitea 镜像各分支最近 100 条提交补充本站账号及已配置展示别名的提交，按 SHA 去重保存到 `repo_snapshots` 的 `mirror-commits:v1`，与贡献记录按仓库和 UTC 日期合并，保留更完整的每日计数及已有历史。内容无变化不写回；不增加定时任务。镜像同步每轮比较 GitHub/Gitea 默认分支的实际 SHA，不使用 `pushed_at` 判断 Git 已同步。


镜像同步器串行执行周期发现和事件请求，完整读取 GitHub 仓库分页，按 `pushed_at` 与上次成功检查点决定是否请求 Gitea `/mirror-sync`；请求入队不算完成，等待 Gitea 成功拉取时间变化并核对默认分支 SHA 后才写入检查点。同步结束一次原子发布目录快照；单仓库失败保留原可用条目，新失败仓库不冒充 ready，也不阻塞其他成功仓库的索引。Go 收到结果后清缓存并立即同步仓库索引，失败不消费事件。实际代码拉取由 Gitea 执行，不由 Go 或发现脚本直接改 Git 文件。

2026-11-11 修复部署：Gitea 的 Git 子进程 HOME 为 `/data/gitea/home`，在该持久化 HOME 的 Git 配置中为 `https://github.com/` 指定服务器现有代理 `http://host.docker.internal:7892`。配置仅作用于 GitHub；此前直连/不可靠路由导致镜像拉取超时。空的失效 `mirco-light` 迁移占位已经备份后通过 Gitea API 重建，未修改 GitHub 源库；备份位于 `runtime/backups/gitea-mirror-repair-20261111`。

以上为当前默认实现，实际调度入口在 `quartz-server/internal/application/runtime.go`。更改周期或触发机制后应同步维护本文。

## 4. 两者之间的协议

1. Quartz 成功发布页面及私有快照后，向 `runtime/events/published.sock` 发送 `POST /published` 通知。Go 只读取固定的 `runtime/chronicle/articles-index.json`，不接受调用方指定文件路径。该 socket 不挂到公网 HTTP/Nginx。
2. Quartz 写构建状态，宿主观察器写 `observer-state.json`，Go 消费并写 MySQL 纪事。
3. 管理员保存配置先保存到 MySQL；需要重建的发布规则通过 Go 请求 `quartz-build.sock` 生效。保存草稿与完成重载是两个阶段。
4. Go 挂载 `runtime/chronicle/` 为只读；`runtime/events/` 由 Go 创建通知 socket，Quartz 只读挂载后连接。构建通知会合并，失败后 Quartz 每 15 秒重试投递，Go 的失败任务同样延时重试；成功空闲后不再产生定时检查。请求重载沿相反方向连接已有 `quartz-build.sock`，不由 Go 启动 Quartz 子进程。
5. 浏览器不直接连接 MySQL。公开页面不获得第三方管理员凭据；管理员在服务接入表单可通过受保护、禁止缓存的接口回显 GitHub Token 与 Bilibili Cookie。页面 API 经 Nginx 转到 Go；文件访问、评论组件和官方播放器保留各自已有的公开入口。

## 5. 运行、更新与故障边界

两个源码工程独立维护，容器统一由 `quartz4/docker-compose.yml` 管理：

```sh
# Quartz、Go、MySQL、站点 Nginx、现有 Artalk
cd /home/goblincwl/docker/quartz4
docker compose up -d --build

# 宿主 Go 容器观察器
systemctl --user status quartz-observer.service
```

- 修改页面、组件、浏览器播放器：在 `quartz/` 维护；当前绑定挂载范围内的改动可触发 watch，依赖或镜像内容变化需重建容器。 修改 CLI 主进程、构建进程管理或源码监听策略后，需要重启 Quartz 容器加载新入口；页面组件和文章仍按原规则热更新。
- 修改 API、同步、认证、数据库：在 `quartz-server/` 维护，在根目录执行 `docker compose up -d --build server` 更新 Go 容器。重启会中断当前进程内的媒体会话。
- 修改库表：开发时调整现有数据库，同步维护 `quartz-server/database/init.sql` 和库表文档。启动不检查或修改结构，不维护增量 SQL 和版本账本。
- Quartz 停止：已有静态产物和 Go API 可继续服务，文章更新与重载不能完成。
- Go 停止：静态文章仍可读取，管理、动态索引、统计和本站媒体代理不可用；部分动态页面的路由校验也依赖 Go。
- MySQL 不可用：Go 就绪检查失败，需要修复数据库；不能通过新建空库假装恢复。

Go 健康端点：`/health/live` 检查进程存活，`/health/ready` 检查应用及数据库就绪；就绪不代表所有第三方平台都可访问。

## 6. 网络、观察器与备份

Go 加入 `service_net` 接受 Nginx 请求，同时加入私有后端网络访问 MySQL；Go 不映射宿主端口。MySQL 加入私有后端网络，另通过专用 `database-access` 网络发布宿主端口，并映射宿主 `3306` 供数据库客户端连接；使用 `quartz` 库和 `quartz` 用户，部署密码明文维护在根 Compose 环境变量中。站点 Nginx 当前映射宿主 `10002`，公网 HTTPS 由外层反代提供。

`quartz-observer.service` 是宿主辅助任务，不是第三个业务 Web 服务：只观察固定容器及恢复情况，写私有状态快照，再由 Go 入库。Web 容器不持有 Docker socket。观察器停止只影响对应容器事件的纪事采集，不承担页面、认证或媒体接口。

备份至少包含：

- MySQL 数据，以及 `runtime/server/auth/` 身份和加密密钥。
- 两个工程源码/配置、两层 Nginx 配置和包含部署密码的 Compose。
- `runtime/chronicle/` 中的发布规则及必要状态；运行中的 socket 不作为恢复数据复制。
- OpenList、Jellyfin、Gitea、Artalk 等按各自职责独立备份。

生产 MySQL 卷 `quartz-server_mysql-data` 在根 Compose 声明为 external，复用已有数据且不会随 `docker compose down -v` 删除；不要手动删除或替换这个卷。迁移前备份是恢复材料，不能在生产已产生新写入后直接恢复旧 SQLite；应先备份并核对新增数据。

## 7. Nginx 与 Go 网关规则

本站 Nginx 把 `/api/*` 与 RSS `/index.xml` 统一交给 Go；新增本站接口在 Go 注册和维护，不再添加逐接口 Nginx location。Nginx 保留静态资源、页面 shell、错误页、压缩缓存和入口连接保护。

- Nginx 从可信外层代理确认真实客户端 IP，覆盖传给 Go 的 `X-Real-IP`，清除调用方自带的 `X-Visitor-IP`。Go 按接口用途派生访客身份，不信任该伪造头。
- Go 对公开只读接口限制 GET/HEAD，隔离无关 Cookie、Authorization、上游 API Key；星枢 Cookie 和分享授权头仅在需要的接口保留。
- Go 对普通写请求限制 1,000,000 字节，分享写接口 128 KiB，媒体 JSON 接口 64 KiB；超过限制返回 413，分块请求同样检查。
- 访客写入由 Go 按真实 IP 限流，持续速率每分钟 30 次，支持短时突发；超限返回 429。原有管理员认证及反馈限流独立保留。
- 普通接口使用有限请求上下文；视频流、测速、仓库原始文件和源码包下载不设置统一的总时长截止，使用连接空闲超时及取消传播，避免长下载被固定时长中断。
- 一言固定调用公开上游，由 Go 合并并发请求、共享缓存十分钟，上游异常时在有效窗口内复用旧缓存。Nginx 不再维护一言业务缓存。
- `drive`、`media` 域名下的 `/api/public/quartz/*` 统一转给 Go，由 Go 提供公开目录及媒体接口的跨域响应。OpenList 原生文件/网页、Fontinass/Jellyfin 原生网页、Artalk、PDF 内联和公开字体入口保持各自域名反代职责。

数据库以当前结构为准，初始化 SQL 位于 `quartz-server/database/init.sql`。原生 JSON、访客外键和级联删除、排序索引保留；删除一次性迁移标记和结构版本账本。

## 8. 统一索引与访问接口

正常页面不再生成或请求 `/static/contentIndex.json`，也不注入全局 `fetchData`。浏览器的目录、星域统计、标签候选、星轨、流新和拾遗共享 `/api/site/content` 的并发合并与短时缓存。搜索仍按关键词调用 `/api/site/content/search`。Repo 将默认分支根目录 README 正文加入索引，按提交 SHA 缓存；Share 将分享首页直接项目的名称加入索引，列表读取缓存 5 分钟，本地分享操作主动失效缓存。仅读取这一层，不递归扫描目录或索引管理员空间。加密分享仍不写入可搜索正文；上游失败保留已有完整索引，不能把失败作为空列表。Repo、Share 的正文、简介和标签均支持关键词匹配。Repo、Share 搜索预览与悬停预览复用渲染及面包屑，无 README 仓库不生成预览。

文章目录只取 `type=article`；Share、Repo、Video 各自的目录分支保留。原始文章相对路径由成功构建快照写入 `extra.filePath`，统一索引对文章同时提供正确的 `filePath`，以保留原始目录名。隐藏规则在发布快照前生效；不额外暴露仅链接可见的文章。

普通索引、流新及 RSS 的数据库读取不取整篇正文和搜索文本；搜索、标签更新等确需这些字段的操作仍读取完整记录。Quartz 的 `SiteMap` 插件仅维护站点地图和 RSS 发现链接。

| API | 用途 | 返回与调用时机 |
| --- | --- | --- |
| `POST /api/visitors/visit` | 记录真实页面导航 | 仅 `meteorId`、`isNew`；机器人忽略时返回 202，不查询总数、今日数或历史列表 |
| `GET /api/visitors?days=30` | 彗星统计及展示摘要 | 页面存在彗星展示模块时读取；不会记录访问 |
| `GET /api/visitors/records?page=1` | 分页历史与筛选 | 用户打开来访详情时读取，支持地区和日期筛选；不会记录访问 |

`isNew` 表示新访客身份，不是新增一次页面浏览。记录接口仍按访客身份和日期去重，并维护最近访问时间。首页初次统计会短暂等待本次记录完成，避免记录完成通知再触发一次相同读取；等待有上限，不能阻塞正文导航。历史列表不再通过统计接口的 `records=1` 分支获取。


## 9. 身份与标签维护

身份读取统一为 `/api/site/session`，Share 页面按需追加 `share=true`。本站状态、TOTP 状态及经后端校验的 OpenList 身份从同一入口返回；来源故障不影响本站登录状态。浏览器缓存只服务界面展示，管理写入仍独立验证会话。

标签查询统一读取 `content.tags`，不再维护 `content_tags`。文章的标签编辑及标签页增删文章关联，会按索引中的 `extra.filePath` 修改原始 Markdown frontmatter（`tags`，兼容原有 `tag` 写法），再由 Quartz 热更新成功快照更新索引。文章不设置或保留 `tagsManaged`，Obsidian 中的修改始终是来源。保存文件与构建发布之间，索引暂时保持旧数据。标签星河项目弹框增减文章关联后，在本次操作内等待新标签进入已发布索引，再刷新当前页面一次；等待可随离开页面取消，最长 45 秒，不设置常驻轮询。

Go 通过 Compose 将笔记目录读写挂载至 `/sources/notes`，配置为 `ARTICLE_DIRECTORY`；日记单独挂载保持只读。宿主笔记目录为 UID 1000 配置访问及默认 ACL，保证现有目录和新建子目录可保存，服务仍以 UID 1000 运行。写入限定为该目录内的普通 `.md` 文件，使用受限文件根、同目录临时文件和原子替换。仅修改标签属性，保留正文、其他属性、BOM、换行格式和文件权限。批量操作先准备全部修改，失败时尽力回退已写文件；回退也检查内容，避免覆盖外部新编辑。写入前检查内容及文件身份，属于乐观并发保护，不承诺与 Obsidian/Syncthing 跨进程事务。临时文件由 Quartz 监听器忽略。

Repo、Video 仍直接维护索引的人工标签集合（`extra.tagsManaged`）；Share 编辑分享继续维护 OpenList 备注并同步索引。标签页对非文章项目的通用关联操作仍直接维护索引人工集合，来源同步保留该集合（包括空集合）；恢复默认后重新跟随 `extra.sourceTags`。


### 文章引用外部来源项目

文章可使用普通 Markdown 网站链接引用项目，例如 `[CwlWeb](https://goblincwl.site/Repo/CwlWeb)`，以及本站 `/Share/分享/<分享标识>`、`/Video/<BV号>` 项目首页。Quartz 根据 `baseUrl` 校验本站主机，按 URL 路径提取关系，将正文链接标记为站内链接，保留显示名称、查询参数与锚点，关系目标统一为无参数、无锚点、无末尾斜杠的解码 slug。外部域名与管理员空间不纳入这类引用；项目内部文件、分类和子目录不作为项目首页引用。

文章成功快照保留这三类项目引用，即使目标暂未进入索引也不丢弃。Go 沿用现有 `content.links` 存储，星轨读取统一索引时只连接当前存在的目标，因此目标后续同步或被移除无需重建文章、增加关系表或周期任务。普通文章链接仍按原有公开范围过滤，分享引用不改变提取码及资源权限。仓库悬停复用 README 预览，分享继续遵守已有解锁及媒体预览限制，视频复用现有悬停视频预览。

## 10. 目录树数据来源

文章、Repo、Video 的全站目录树共享 `/api/site/content`，不再为导航读取 `/api/repo/catalog` 和 `/api/video/library`。首页仓库、视频数量也从同一索引统计。模块页面中需要的仓库、视频详情仍调用各自业务接口。

Repo 使用 `extra.language` 分类，Video 使用 `extra.series` 中稳定的系列标识及名称分类，与管理员人工标签独立；系列和视频按最新发布时间排序，“其他”固定最后。视频周期同步更新系列元信息后，统一索引随之更新。

Share 单独处理：公开入口、访客文件、分享内部目录继续使用 OpenList 适配读取；管理员空间另外授权。加密分享的解锁状态及内部目录缓存不混入公共索引。


## 11. 归属地数据和星历

GeoIP 的 gzip XDB、校验值和来源版本统一保存在 MySQL `geoip_datasets`。启动只读取和校验参考数据，加载内存后查询，不恢复文件挂载；数据库结构仍通过开发维护，不在启动时修改。数据更新使用明确的 `quartz-admin import-geoip` 操作，IPv4/IPv6 同事务替换，重启后端生效。

星历查询以指定月份为中心，一次返回前、当前、后三个月，日记解析结果分别存为 `attendance:YYYY-MM` 快照；`attendance` 只保留日期范围和同步状态。前端首页与详情共享有限月份缓存；命中相邻月份时直接切换，首页保留星光过渡，详情使用缓存避免短暂 loading。缓存过期可保留已有视图等待刷新，不预加载完整历史，不允许旧请求覆盖新选月份。


## 12. 本机维护入口

以下命令在部署根目录执行，管理员维护使用现有后端，不增加独立服务：

```sh
cd /home/goblincwl/docker/quartz4
docker compose exec server quartz-admin set-password
docker compose exec server quartz-admin reset-totp
systemctl --user status quartz-observer.service
```

更换 GeoIP 数据集时，临时目录内放入 `ip2region_v4.xdb`、`ip2region_v6.xdb` 和来源 `source.json`，显式导入后重启加载：

```sh
docker compose run --rm --no-deps -v /绝对路径/临时数据目录:/geoip-import:ro --entrypoint quartz-admin server import-geoip /geoip-import
docker compose restart server
```

运行变量由 Compose 维护：`SITE_ORIGIN`、`MYSQL_ADDR`、`MYSQL_USER`、`MYSQL_DATABASE`、`MYSQL_PASSWORD`、`AUTH_DIR`。站点和数据库密码配置的维护位置为根 Compose；TOTP 与访客身份密钥仍在私有运行目录，不能仅备份数据库。


## 告警中心

星枢管理的“告警中心”只供已登录管理员读取，支持类型、关键字与分页，刷新由进入模块或手动操作触发，不设前端轮询。后端固定读取 `GET /api/site/admin/alerts`，不提供公开读取或客户端提交告警的入口。

采集复用已有执行链路：外部 HTTP 调用记录连接失败及 HTTP 401/403/429/5xx，Bilibili 与部分 OpenList 接口另外记录业务错误；普通 400/404 和用户取消不视作通用接口故障。后台周期及事件任务在已有失败分支记录异常。服务异常复用宿主观察器现有十秒采样，连续两次非正常样本后写入快照，由既有服务纪事消费流程在事务内去重记录；不新增探测周期或数据库权限到观察器。

告警记录写入 MySQL `alerts`。同一来源、类别、标题、目标与错误码连续发生时累计次数；同类异常静默超过十分钟后新建记录。每次新建时按最近发生时间保留最新1000条，不设清理任务。此版本是异常历史记录，不将记录存在解释为服务当前仍未恢复。

请求和任务通过有界事件队列异步写入；只有收到事件时才执行，不设定时器。队列已满或数据库写入失败时回退进程日志，避免阻塞业务或递归生成告警；进程退出时限时处理已排队记录。数据库或 Go 自身不可用期间不能保证立即落库，观察器保留的异常快照可在恢复后补录。

HTTP 观测不读取或改写响应正文，也不改变重定向、连接池和媒体流处理。只保存目标 origin、状态码及安全摘要，不保存 URL 用户信息、资源/会话路径、查询参数、Authorization、Cookie、Token、API Key 或上游响应正文。

### 浏览器文字字幕外观

Jellyfin 文字字幕沿用 GoblinCwl 的网页外观：Custom、large、bold、casual、透明背景、白色、默认阴影、垂直位置 -2。字号按 Jellyfin 自定义容器 170% × large 1.72em 计算；字体候选为 Gabriola、Segoe Print、Comic Sans MS、Chalkboard、Short Stack 和系统备用字体，由观看设备提供。没有独立的星枢默认字体配置。文字层使用浏览器 TextTrack 的 cuechange 与当前活动字幕，不维护第二套播放时钟；双语换行和字幕内标记由 getCueAsHTML 保留。系统原生全屏保留原生字幕通道。ASS 仍使用自身样式及字体，PGS 保持图像或 Jellyfin 烧录，不套用文字字幕默认外观。播放设置的「字幕外观」打开带实时预览的表单，支持原生/自定义、字号、字重、字体、颜色、描边和垂直位置。调整立即生效，通过父页面保存至当前浏览器的全局 `subtitleAppearance`，不同影片共用；没有服务器账号同步，可恢复上述默认值。原生全屏内打开相同表单，页面正常播放时使用站内弹窗。原有逐片 `subtitleStyle` 仅供普通文件视频预览使用，Jellyfin 不再将其应用到 ASS。

### 可维护的服务状态列表

管理入口为「数据管理 → 服务列表」。`monitored_services` 按单条记录维护名称、已集成服务类型、可选 Beszel 容器名、HTTP 检测地址、可选认证、启停与排序；现有 11 项只作为初始化 SQL 的初始数据，不在启动时补回或重建。关闭或删除只影响状态列表，不停止宿主服务，不修改原服务接入配置，也不改变既有宿主机观察程序。内部服务的 HTTP 地址由配置解析，只读回显且不能在条目中覆盖；只有其他来源可填写 HTTP 地址。来源包含 quartz-server，其检测地址为 `/health/ready`。检测认证在条目内选择无、Basic、Bearer 或自定义请求头，按类型显示字段，服务和认证在同一事务保存。认证密钥加密存储，留空保留；删除或解绑后清理不再引用的检测凭据。
Syncthing 仅作为普通监控数据维护：不提供业务接入配置或已集成服务预设，HTTP 地址直接保存在 `monitored_services.http_url`。NapCat 保留 QQ 在线状态业务接入。宿主机观察程序的既有恢复检测独立于业务集成分类。


添加时可选择已集成服务或其他服务。集成条目的 HTTP 地址留空时，检测时引用原服务地址及既有路径；其他服务只需填写名称和 HTTP/HTTPS 地址，默认无需认证。容器名称为空时只使用 HTTP；有容器名称时优先使用 Beszel 的有效状态，Beszel 不可用、对应容器缺失或超过 3 分钟时改用 HTTP。不用 HTTP 成功覆盖 Beszel 已确认的停机或不健康状态。Fontinass 的原服务接入检测配置保留；上一版新增的固定检测地址项已移除，有用户保存值时一次性保留到对应服务条目。

`service_credentials` 独立维护可选 Basic、Bearer Token、自定义请求头认证，密码/密钥使用既有 AES-GCM 密钥加密，管理读取不回显密钥。被服务引用的认证不可删除；认证只用于状态检测，不复制或改写平台接入账号。公共接口只返回已启用项的标识、名称、图标、状态和状态来源，不返回地址或认证信息。新增、修改和删除后使原 30 秒共享状态缓存失效；延用可见星枢页面 30 秒刷新、单次 2.2 秒超时，HTTP 并发最多 8 个，不新增周期任务。右侧服务区保持高度预算内的固定可用区域，从顶部按自然行高排列并内部滚动。


### 字幕默认选择与管理安全

Jellyfin 媒体查找请求 `PlaybackInfo?UserId=...`，由 Jellyfin 按接入账号的语言、字幕模式及记忆生成 `DefaultSubtitleStreamIndex`，本站只传递结果。空值/-1 表示关闭，不再在 Jellyfin 播放链路猜测标题中的中文/双语或优先文字格式；本站明确保存的字幕选择或关闭仍优先。普通文件预览的选择独立于此逻辑。

Safari 及 iOS 浏览器的 Jellyfin 字幕统一由 Jellyfin 烧录，使用已固定版本 Jellyfin Web 的浏览器识别结果。该策略在首次协商前生效，覆盖 ASS/SSA、PGS 和普通文字字幕，切换音轨、画质及续播保留当前烧录轨道；关闭字幕则请求 `-1`。不下载或挂载网页字幕图层，不在 HLS 清单添加可被系统自动启用的外部字幕组，也不提供无效的字幕外观/偏移设置。代价是启用字幕时需要视频转码。其他浏览器保持原有字幕渲染与用户偏好，Safari 策略不写回用户偏好。

星枢「账户」提供重新绑定令牌。`POST /api/site/admin/totp/rebind` 除现有管理员会话和来源校验外，还验证密码及当前动态码/一次性恢复码；新密钥仅保存在限时内存凭证中，确认新动态码前保留原绑定。复用 `/admin/totp/confirm` 原子替换绑定、作废旧恢复码与全部旧会话；保存新恢复码后经 `/admin/totp/finish` 发放新会话。重绑证明绑定客户端 IP、阶段及当前认证版本，过期、重放或认证状态变化时失效；不增加清理或轮询任务。

外部平台 HTTP/API 失败和 GitHub/Bilibili 同步失败记为警告；集成内部服务的连接/服务故障仍记为错误。其他来源的自定义状态条目记为警告。连续同类异常仍按既有十分钟静默窗口合并次数，不额外轮询。


文字字幕按实际媒体画面等比例缩放：以当前显示器适合媒体方向的最大全屏画面为基准，按视频固有宽高比计算播放器内不含黑边的画面矩形。自定义文字层以该矩形为边界，字号、换行、行距、阴影和垂直间距整体同比缩放；浏览器原生文字字幕采用相同比例计算字号。视频分辨率不参与字号计算，1080p/4K 的相同画面比例得到相同显示大小。全屏、网页全屏、窗口尺寸、屏幕方向及媒体元数据变化复用已有尺寸事件更新，不增加轮询任务；ASS/PGS 和烧录字幕不套用文字样式。

### 播放器浮层边界

播放设置和弹幕设置共用主题色、标题、圆角、关闭图标和悬停反馈。通过现有 iframe 消息通道，在菜单超出媒体高度时按可见视口预算临时扩展 iframe 的上部透明画布；负外边距抵消占位高度，播放器实际媒体尺寸不变。扩展区域裁剪为菜单宽度，避免挡住旁边正文。关闭、全屏和页面退出时回收；仅依赖尺寸、滚动、菜单状态事件，无轮询。视口不足时菜单内部滚动。

字幕外观弹窗打开时聚焦容器，保留关闭按钮的键盘可达性；字幕预览使用固定多彩渐变背景，用户设置仍只影响字幕文字。


### Safari 原生字幕与拖动后的同步

文字字幕以横屏 1920／竖屏 1080 的设计宽度归一字号，再按实际显示画面缩放，避免手机屏幕尺寸较小时仍套用桌面字号；自定义文字层关闭 Safari 的文字自动放大。Safari 原生视频全屏不写入内联播放器的 `::cue` 像素字号，由系统字幕视口决定大小。`webkitendfullscreen` 事件优先于可能滞后的 WebKit 属性，退出时先关闭原生字幕轨，再恢复唯一内联渲染层；原生字幕轨后续模式变化仍校正为当前选择。

ASS 继续使用现有 libass 渲染，不修改字体或字幕时间内容。拖动、缓冲时暂停 worker 的时间推算，拖动完成、播放恢复、倍速变化时用 video.currentTime 与用户偏移重新同步，页面退出或字幕更换后移除监听。字幕切换完成即清除切换加载标志，恢复播放不再阻塞该标志。PGS 默认仍由 Jellyfin 烧录；烧录失败不再重复同一个烧录请求，独立文字渲染失败时的烧录回退保留。

图片灯箱使用浏览器原生模态 dialog 保持原动画和操作栏，背景交互由模态顶层阻断，滚动锁复用 lockPageScroll。关闭动画结束前不释放模态阻挡；关闭、导航时释放本次持有的滚动锁，避免影响其他抽屉或弹窗。

全站标签入口统一为 `/tags/?tag=<标签名>`，标签名按完整字符串 URL 编码，含 `/` 的子标签仍作为一个查询值。构建仅生成 `tags/index.html`，不再生成独立标签筛选页，也不保留动态筛选路由 API。直达链接在索引就绪后定位星团并展开项目弹框，关闭面板清除 `tag` 参数，其他访问参数保留。弹框按每批 20 项渐进渲染，用内部滚动触底追加，不额外请求整套索引；悬停预览沿用四类内容已有组件与权限规则。管理员增减标签项目操作保留在弹框内。

### 移动端抽屉与来访详情

底部抽屉由 CSS 在对应布局断点声明 `--site-drawer:1`，共用 `showSiteDialog` / `closeSiteDialog` 的进入、收起及 Esc 动画。关闭动画被重新打开打断时取消旧回调；路由销毁和断点布局切换仍调用原生 `close()` 立即清理。减少动态效果时不播放动画，普通居中弹窗保留原有交互。首页“与我联系”在移动端与其他首页详情统一为底部抽屉，并锁定背景滚动。

`/api/visitors/records` 服务端只查询上海时区当前日与前六日有来访的记录（依据 `last_seen`），分页、地区和首次来访日期筛选都不能突破此范围。来访地区分布独立查询原有历史统计，返回 `distributionTotal` 用于占比；`/api/visitors` 汇总和统计图表查询不受七天限制影响。前端日期选择同步限制最近七天。

### 站内 404 与代理错误页

站内导航的 404 使用独立构建产物 `/static/site-404.html`：复用目录页的左侧导航、搜索与明暗切换，不包含阅读模式按钮或评论；正文参考加密文章的居中图标与提示布局，仅占正文栏，保留右侧空白区域，不提供额外按钮。SPA 收到页面 404 或 `quartz-not-found` 事件后加载此产物，保留用户请求地址；相对链接以站点根路径解析。缺失此产物时保留原有错误响应，不能递归请求自身。

本站网关对不存在地址的直接请求、刷新和站内导航，均通过内部 `/_site_not_found` 返回带左栏的页面，保留原请求地址和 HTTP 404，并设置 `X-Site-Error: 404` 避免前端再次请求页面模板。API 的 JSON 错误响应不拦截。`/403.html`、`/404.html`、`static/errors/*` 及 `runtime/errors/{403,404}.html` 使用共用 ErrorNotice 组件导出的独立 HTML，无侧栏和按钮，内嵌 SVG、动效 CSS、系统字体栈和头像 ICO，按系统明暗偏好显示，无外链资源或运行脚本。403 使用星光触及边界后返回的动态图标与“光锥之外／星海无垠，所见终有边界”，404 沿用迷航星轨和原文案；导出格式与站内正文共用样式，后续不会各改一套。构建时直接生成并原子替换持久文件，不再等待或内嵌整站 index.css；现有前置 Nginx 的共享挂载自动读取新文件，服务异常时仍能独立展示。

Repo 请求明确返回 404 时进入同一站内错误页；网络失败、服务超时和可选 README 加载失败仍留在当前模块处理。不存在的 Repo 语言分类/视图，以及无效 Video 路径、缺失 BV、缺失系列也进入站内 404。视频库中已有但标记失效的项目保留原播放页失效状态，不把任意不存在的 BV 伪装成失效项目。


### 后台任务配置

星枢管理独立「任务」模块统一维护 Go 后台周期及失败等待时间，配置保存在现有 settings 表的 tasks.* 私有键，不向公开设置接口暴露。配置包含网盘/仓库索引、GitHub/Bilibili 动态、ActivityWatch 汇总、视频全量同步及失败重试、服务/构建日志采集、容器状态观察、登录/监控/媒体清理、日历事件合并与监听恢复、文章/权限/凭据事件重试、视频索引重试、友链队列数据库重试及退避初始值/上限，以及友链巡检间隔及时间（默认每天北京时间 06:00）。请求超时、缓存有效期和请求内限流不属于任务周期。

保存后通知相关调度器重新计时，不立即触发任务；正在执行的工作继续完成，下一次使用新周期，不并发重复启动。事件任务仍为空闲等待通知，只有失败时计时；友链持久化工作项已记录的下次执行时间不追溯修改，新失败使用新退避参数。服务重启从数据库恢复配置；友链巡检间隔按固定日历周期安排，重启不推迟。首页重试仍同日最多一次、连续七次失败停用，调整巡检间隔后七次重试也随之调整。宿主观察器通过 runtime/events/task-config.json 接收仅包含观察周期的原子快照，文件变更通过目录监听读取，不连接本站数据库，不包含凭据；服务未启动或配置不可读时保留原周期（首次默认十秒）。

友链固定编号由 friends.number 自增分配，唯一且不随 RSS 排序变化；已有记录迁移时按原公开卡片顺序补齐。原 position 排序列及前移/后移操作移除；编号可在数据维护中编辑，新增留空自动分配。友链管理移除新增入口，保留资料编辑与审核；新增仍可通过访客申请或数据维护完成。星枢管理的「视频」模块展示名称改为「媒体」。


### 视界与本轮界面完善

星垣在标签之前提供「视界」（/reading/），使用站内字体与配色，按最近更新时间倒序双栏展示标题和正文开头，移动端单列，不展示分类、编号、时间、标签等额外信息，下拉接近底部自动加载下一页。GET /api/site/content/reading 每页最多 12 条、每条正文开头最多 2400 字符并标明是否截断（供高卡片按剩余空间填充），SQL 仅读取有限正文片段；沿用统一内容索引的公开范围，不向浏览器传递整篇正文。加密内容不返回正文或简介，局部加密段落同样经现有摘要脱敏处理。页面文本使用 textContent 写入，原文链接限定本站路径。

Repo 的 Markdown 读取完成后主动渲染 Mermaid 代码块，使用本站已有 Mermaid 资源、严格模式及 SVG 清理；坏图保留代码，不影响其他图和正文，页面离开取消后续渲染，主题切换重新绘制。仓库右侧展示 Gitea /languages 提供的默认分支代码字节占比，服务器缓存十分钟，统计失败不阻断代码与 README 展示。

来访地区图的分母从同一份地区直方图的全部计数求和，条形长度与百分比共用该分母；不得使用仅含最近七天的列表总人数。友链本站信息提供本站 /index.xml RSS 地址，每项可单独复制，仍保留复制全部。标签侧栏初次读取使用动画和标签形状骨架；项目弹框按实际视口限高，不再固定 42rem，高屏幕能容纳的项目不额外滚动。

视界保留通用页面宽度与左侧目录网格，仅将内容延展至空闲右栏；移除独立纸张配色、超大刊头与装饰。自动加载串行执行、按 ID 去重，出错保留已加载内容并提供重试，离开页面取消请求及滚动监听。

视界顶部居中显示页面名称及一段短文案，内容卡片采用站内配色，保留自动加载。

视界阅读卡片增加现有四源类型 SVG 与北京时间更新时间，保留轻微页边线和折角；不引入分类筛选或编号。

视界卡片底部提供由原文路径推导的所属文件夹链接、北京时间更新时间与阅读全文链接；长文件夹路径省略显示但保留完整提示，窄屏页脚可换行。

视界默认隐藏未解密文章；成功解密后，摘要仅暂存在当前标签页内存并随 SPA 导航复用，不将明文写入浏览器存储或后端。摘要最多保留十二小时，文章更新时间变更后失效。阅读卡片放大标题、正文与页脚字体，正文最多显示四行。

视界的类型识别改为静态背景与边框：文章用低饱和灰绿底和左侧实线，仓库用灰蓝底和顶部实线，分享用浅沙色底和虚线，视频用灰紫底及上下双线。移除标题类型 SVG、卡片 hover 变色和阅读全文箭头位移，仅为可点击链接保留下划线提示与键盘焦点。

视界采用无缝矩形拼接，以标题与正文的实际文本量决定宽度和跨行组合：较长正文形成跨两到三行的纵向块，旁边短内容填充完整；普通内容并排显示，手机按时间顺序单列。移除固定最小高度、像素行跨度和 ResizeObserver 占位，减少空白并保持每个拼接带无洞。背景 SVG 专为铺底重绘，亮暗主题分别调整线条颜色与透明度；类型边框强化书脊线、代码括角、窗口内框与胶片齿边。首次及追加读取均使用翻书与星点 SVG 动画，不使用骨架。

视界解锁判断统一覆盖所有加密类型，不为受保护分享保留占位卡片。已验证的解密摘要优先于索引摘要，局部 Meld 解密通过 reading-content-unlocked 事件更新预览。存在缓存 AES 密钥时校验当前 payload 版本后在浏览器重新解密正文；存在分享提取码时通过既有权限接口验证并重新读取内容。密钥/提取码过期、错误、正文读取失败均隐藏该项，不回退到加密前索引；浏览器存储仍仅保存既有凭据，不保存新增明文。

视界类型色相与 graphPalette 对应：文章青绿、分享红、仓库紫、视频蓝紫；视界独立提高饱和度与明暗对比，不直接复用星轨节点淡色。亮暗主题分别配置，边框加强书脊双线、代码括角、连接框及胶片齿边。

视界在内容区域右侧保留窄年月时间轴，按北京时间归月，支持滚动高亮和点击定位；未加载月份按序补读后定位，隐藏内容不生成目录月份。窄屏转为顶部横向月份导航。亮色背景 SVG 提高线条可见度，暗色保持独立透明度与遮罩。

视界隐藏主内容末尾的通用分割线。文章边框使用重复装订环、书脊带与底部页层，仓库边框改为提交节点和分支汇入轨道，替代抽象括角。

视界文章与仓库的边框装饰限制在 6px 边缘带：文章为双线书脊和底部页层，仓库为顶部提交节点线及短端框。移除正文区内装订环、38px 分支轨道和专用左缩进，所有类型共享内容内边距。

视界边框继续限制正文侵入范围：文章装订细节宽 12px，仓库分支轨道高 12px，不添加类型专用正文缩进。视频上下改为细边加空心胶片孔，取消整条粗色线，避免相邻视频边框叠成粗带。

Repo 边框移除左上代码符号，保留四角压边和右下小分支。所有背景图由 ResizeObserver 根据卡片实际宽高调整缩放、偏移与旋转；纵向视频以纵向胶片呈现，书页和编辑器不做九十度旋转。背景图绝对定位，不参与占位或压缩正文，离页释放观察器。

内容发布的 `content.directoryHiddenPatterns`（仅隐藏目录）与隐藏展示分开维护，使用相对文章根目录的目录、文件或 glob，每行一条。保存后通过原有站点重载应用到 Quartz；仅过滤左侧目录树和文件夹列表；直接打开命中的文章（含别名入口）不自动展开或定位目录，并隐藏面包屑导航；不移除内容索引，不影响星轨图、搜索、流光或原文访问。与构建排除、隐藏展示同时命中时，后两者仍生效。已有生效规则文件未包含此项时按空规则兼容。
